## Description

Redesign the View DevKit UI (`packages/sdk/src/devkit/app.html`) to match the KitStack design language used in the web app. This is a **UI-only** task — do not change the JavaScript logic, postMessage protocol, loader/tool endpoints, or Vite integration.

### Context

The DevKit is a local preview server for kit views (`kitstack dev --views`). It shows a sidebar with views, a viewport with the rendered view in an iframe, and bottom panels for data inspection, tool call logging, and viewport controls.

Current state: functional but generic-looking (plain HTML/CSS, no brand alignment). Needs to look like it belongs to the KitStack product.

### Research first

Before implementing, study these references:

1. **KitStack web app** — look at `web/src/app/` for the existing design patterns:
   - `web/src/app/dashboard/` — layout, cards, sidebar patterns
   - `web/src/app/skills/page.tsx` — listing page with cards
   - `web/src/app/kits/` — kit detail pages
   - `web/src/components/shared/nav.tsx` — navigation bar
   - `web/src/components/ui/` — reusable UI components
   - `web/src/app/globals.css` — global styles and CSS variables

2. **KitStack Tailwind preset** — `packages/sdk/src/tailwind-preset.ts` defines the `ks-*` color palette, font families (Instrument Serif, Inter, JetBrains Mono), and typography plugin. Use these tokens.

3. **Similar developer tools for reference** (search the web):
   - Storybook's UI (sidebar + preview + addon panels)
   - Chrome DevTools (panels, tabs, inspector)
   - Vercel's preview deployments UI
   - Figma's dev mode inspector
   - Linear's UI for clean, minimal developer tools

### What to redesign

**File to modify:** `packages/sdk/src/devkit/app.html` (the `<style>` block and HTML structure)

**Header bar:**
- Use KitStack brand colors (ks-ink background, Inter font)
- Kit name, tool/view count
- Reload button styled consistently

**Sidebar:**
- View list with active state highlighting
- Use ks-accent for active indicator
- Show view descriptions in a subtle way
- Consider grouping or icons

**Viewport area:**
- Clean background (use ks-paper or subtle grid pattern)
- Frame container with proper shadow and border
- Viewport size buttons should look like a segmented control (not plain buttons)
- Smooth transitions between sizes

**Bottom panels:**
- Data Inspector: syntax-highlighted JSON (use JetBrains Mono, ks-paper-warm background)
- Tool Call Log: each entry as a compact card with timing, color-coded by success/error
- Capabilities: clean toggle switches instead of raw checkboxes
- Panel headers should have consistent typography

**Overall:**
- Use the ks-* color palette exclusively (ks-paper, ks-ink, ks-muted, ks-accent, ks-hair, etc.)
- Use Inter for UI text, Instrument Serif for headings, JetBrains Mono for code/data
- Aim for the same warm, paper-like aesthetic as the web app
- Responsive: should look good at different screen sizes
- Dark top bar + warm light content area (like the web app's nav)

### What NOT to change

- The `<script type="module">` block (all JavaScript logic)
- The element IDs used by the script (`view-list`, `viewport-content`, `data-inspector`, `tool-log`, `outer-frame`, `btn-reload`, `cap-clipboard`, `cap-download`, `cap-links`, size buttons with `data-w`)
- The layout grid structure (sidebar + viewport + panels) — you can adjust CSS but keep the three-area layout
- Any endpoint URLs (`/__devkit/shell`, `/__devkit/loader/`, etc.)
