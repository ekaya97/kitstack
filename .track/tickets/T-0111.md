## Description

Plan: docs/company-pivot-plan.md:105-146. Kits need first-class scheduled jobs (cron). This ticket is the SDK half; the infra half (JobDispatcher + schedule sync) is a separate ticket that depends on this one.

API (packages/sdk/src, alongside defineTool/defineView):
defineJob({ name, description, schedule, timeoutSeconds, handler: async (db, ctx) => {...} })
- name: snake_case, validated like tool names (see define-kit.ts validation and packages/sdk/src/define-tool.ts:88 for patterns)
- schedule: EventBridge Scheduler expression string — cron(...) or rate(...); validate parseable at definition time
- handler gets the same drizzle db binding as tools
- ctx.continue(payload): handler persists a cursor (convention: a job_runs table in the kit schema) and requests async re-invocation for work longer than one Lambda run; dispatcher caps continuations per firing (see infra ticket)
- jobs: [...] added to defineKit config (packages/sdk/src/define-kit.ts:99) with definition-time validation: unique names, valid schedule, description >= 10 chars

BUILD (packages/sdk/src/build.ts):
- Generated Lambda handler (build.ts:222-266) gains a third invocation branch: { type: job, jobName, dbUrl, dbToken, continuation? } next to tool and loader dispatch
- manifest.json (build.ts:490) gains jobs array (name, schedule, timeoutSeconds) and per-kit resources { memoryMb, timeoutSeconds } — replaces the hardcoded 128MB/10s in the deploy route (consumed by infra ticket)
- Export defineJob from packages/sdk/src/index.ts:17

ACCEPTANCE: a fixture kit with one job builds; manifest contains jobs + resources; invoking the built handler with a job payload runs the handler; type errors on bad schedule/name at definition time. Existing kits without jobs build unchanged.
