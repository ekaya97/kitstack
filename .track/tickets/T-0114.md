## Description

Plan: docs/company-pivot-plan.md:396-473 (Design points 1, 2, 7). Foundation for shared kit databases: users belong to organizations; the company = one org whose members share data.

1. Add the BetterAuth organization plugin to web/src/lib/auth.ts:14-53 (BetterAuth is already the auth layer, drizzle adapter over the main Turso DB). Generate plugin schema (organization, member, invitation tables) into web/src/db/auth-schema.ts + a drizzle migration in infra/migrations. NEVER use DROP statements in any SQL migration.
2. Personal org per user: auto-create on signup (hook in auth.ts next to the existing early-adopter hook at auth.ts:20-39); backfill migration/script for existing users. ALL later org logic assumes every user has at least one org — one code path, no personal-vs-team branching.
3. Roles: owner/admin/member (plugin defaults). Only owner/admin can invite, change roles, manage kits.
4. UI (style with existing ks-* tokens; WS4 re-theme lands independently): org switcher in dashboard nav (sets active organization on the session — plugin supports this), members page (list, invite by email, change role, remove), pending invitation accept flow. Dashboard lives at web/src/app/dashboard.
5. Session helper: expose active orgId server-side alongside getSessionOrNull (web/src/lib/authz.ts:32) for API routes.

Parallel tickets T-0115 (org-keyed DBs) and T-0116 (authz relations) build on the tables/roles from this ticket — keep the member/role table shapes stable once merged.

ACCEPTANCE: signup creates personal org; user can create a second org, invite another user by email, accept flow works; active-org switcher persists; existing users backfilled.
