Persist only vector + portal_file_url + content_hash (skip unchanged). Discard bytes.

DEDUPE (cross-source entity resolution, non-destructive):
1. Within-source is already exact (upsert on portal+portal_profile_id in T-0117).
2. Blocking: normalized name + city to keep candidate pairs small.
3. Score pairs: name similarity (Jaro-Winkler), skill-set Jaccard, rate proximity, embedding cosine.
4. Above high threshold: auto-merge — repoint freelancer_sources.freelancer_id to one canonical freelancers row (never delete). Gray zone: write merge_candidates (status auto_merged/confirmed/rejected) for later review.
Run order within job: embed new/changed -> dedupe (needs embeddings for scoring).

ACCEPTANCE: kitstack job run dedupe_and_embed on a dev DB with both portals ingested produces embeddings for all profiles + docs, merges an obvious duplicate fixture, writes gray-zone candidates; idempotent re-run does ~nothing (hashes); unit tests for scoring with fixture pairs.
