## Description

Found while building kits/adint (the dogfood loop). packages/sdk/src/build.ts:163 and runtime/dev-db.ts:57 split migration SQL with a plain String.split(';'). Any ';' inside a string VALUE (e.g. ad landing/clickthrough URLs) or inside a COMMENT line splits the statement mid-token, producing a broken or comment-only fragment that libSQL rejects with 'SQLITE_UNKNOWN_0: not an error'.

Repro: seed a row whose text value contains ';', or put ';' in a -- comment. Build fails at that statement.

adint worked around it by URL-encoding ';'->'%3B' in seed values and keeping ';' out of comment lines — but that is a kit-side hack for a platform limitation. Real fix: split respecting quoted strings and line comments (a tiny SQL tokenizer), or support an explicit statement separator. This will bite any kit that seeds real-world text (URLs, HTML, prose).

See .track/docs/adint-domain-reference.md §9 and .track/specs/adint-kit-spec.md.
