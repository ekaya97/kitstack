## Description

Plan: .track/docs/sales-voice-agent-demo-target-plan.md §W1 (lines 176-199). Review: §3.1 and §3.3. Tier 2.

## Goal
Make the already-connected Claude Web connector (`mcp.kitstack.co`) reach the sales debrief kit on the voice service, with no app-token copy/paste.

## Reality check (from review)
- The router exposes exactly two MCP tools, `kit` and `kit_view` (`packages/mcp-server/src/router/mcp-protocol.ts` → `packages/sdk/src/server/protocol.ts:95-189`). Kit actions are reached as `kit(id="debrief", cmd="prepare_debrief", params={...})`.
- `platformAdapter.resolveUserKits` only returns kits with a per-user Turso DB; `executeTool`/`executeLoader` invoke a registry Lambda ARN (`packages/mcp-server/src/router/platform-adapter.ts:35-129`). The debrief kit has neither.

## Scope
- In the platform adapter, inject a virtual `ResolvedKit` for id `debrief` (tools from `kits/debrief` contracts, views from T-0195) and short-circuit `executeTool`, `executeLoader`, and `getShellHtml` for that kit id before the Lambda/Turso path. Existing kits are untouched.
- Add MCP auth mode `internal-signed` to `packages/demo/src/auth/mcp.ts`: short-lived JWT signed with new secret `KITSTACK_DEMO_INTERNAL_SECRET`, claims `{ sub: userId, org, kit: "debrief", req, trace, exp }`. Copy the `jose` pattern from `router/app-token.ts`; do not reuse its `{sub, kit}` claim set or the static `mcpInternalApiKey`.
- Voice service maps `userId → orgId` through a static allowlist (one demo org); unknown users → 403 → useful MCP error.
- Wire the secret and voice-service URL in `infra/secrets.ts`, `infra/mcp.ts`, `infra/demo.ts`. Keep `app-token` mode for the direct `/mcp` local/fallback path.
- Timeout + error mapping: unavailable voice service returns a clear MCP error, not a generic Lambda failure.

## Acceptance
- From the existing connector: `kit()` lists `debrief`; `kit("debrief")` lists its actions; `kit("debrief","prepare_debrief",{...})` reaches the voice service and returns the T-0184 output.
- Existing kits, OAuth discovery, and router tests remain green.
- No presenter-side token handling.

## Write scope
`packages/mcp-server/src/router` adapter/dispatch files, `packages/demo/src/auth/mcp.ts`, `infra/mcp.ts`, `infra/demo.ts`, `infra/secrets.ts`, integration tests. May run in parallel with T-0186 (different packages).
