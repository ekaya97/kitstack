## Goal
Replace the goal-only, in-memory session model (`packages/demo/src/debrief/index.ts:60`) with a small customer-specific persistence layer.

## Scope
- libSQL tables: `demo_customers`, `demo_customer_events`, `demo_debrief_sessions`, `demo_debrief_drafts`. Use the additive migration pattern already in `packages/demo/src/telemetry/index.ts:159-160`.
- Add `customer_id` to `telemetry_events` (needed by T-0193 filters).
- Normalize company/contact/location; match an existing customer by stable org-scoped identity.
- Persist session state, callback time, scheduled call time, call ID, instruction version, memory references, and draft fields. Route all writes through the `persistence:libsql` plugin boundary so `plugin.invoked` telemetry stays complete.
- Structured facts and operator notes only; never transcript/audio.
- Reads are customer- and org-scoped.
- Extend `DemoApp.reset()` (`packages/demo/src/app/index.ts:177`) to clear the new tables while preserving app credentials.
- Keep existing memory tables; link approved memories to customer/session context.

## Acceptance
- A process restart reloads a prepared session and its customer context.
- A second prebrief retrieves the latest approved customer events and memories.
- Isolation tests prevent cross-customer and cross-org reads.
- Reset leaves no customer/session/event rows; dogfood test (`packages/demo/src/dogfood.e2e.test.ts`) and 97/97 demo tests stay green.
