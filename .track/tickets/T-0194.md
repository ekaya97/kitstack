## Description

## Goal
Prove the exact presenter sequence through the local OpenAI Realtime path,
with shared-store persistence, dashboard evidence, and a rollback/recovery
path. Twilio remains a connector seam and is not required for demo acceptance.

## Scope
- Record the last known-good commits for the MCP router and the voice service before deploying.
- Deploy the MCP adapter (T-0185) and voice-service changes to the selected
  stage when deployed evidence is required.
- Verify existing `mcp.kitstack.co` OAuth and existing kits still work.
- Verify `kit("debrief")` lists the tools and all three Views render.
- Run the exact debrief flow locally; run it a second time to prove memory
  retrieval; reset between rehearsal and live demo.
- Capture screenshots/notes for the demo script.

## Acceptance (from the plan)
1. Existing Claude connector invokes the debrief kit.
2. Prebrief View appears in the chat.
3. Scheduler waits for `scheduled_call_at`.
4. Local OpenAI Realtime establishes the voice session without a dashboard
   start click.
5. Agent conversation calls the declared debrief tools and returns to the same
   session.
6. Editable confirmation View saves the confirmed outcome/address.
7. Customer timeline View shows the new event.
8. Registry/observability/FinOps dashboard shows the same run.
9. A second run retrieves the first run's approved memory.
10. Existing connector/kit smoke tests remain green.
11. Twilio connector seam tests remain green; a live Twilio call is optional
    evidence, not a blocker.
12. The local reset/recovery path and operations safety gate are documented;
    deployed rollback rehearsal remains optional follow-up evidence.

## Write scope
Deployment config, rehearsal artifacts, no new runtime architecture. Tier 1 may be rehearsed through the direct `/mcp` app-token path if Tier 2 is cut.
