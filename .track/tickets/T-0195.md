## Goal
Make `kit_view("debrief", ...)` renderable through `mcp.kitstack.co`: the router's `getShellHtml(kitId)` reads a built app shell from S3 keyed by registry metadata (`packages/mcp-server/src/router/platform-adapter.ts:131-135`), and the debrief kit has no built View bundle and no registry entry.

## Scope
- Build the `kits/debrief` View bundle with the SDK build (`packages/sdk/src/build.ts`) once T-0190 adds the first View; add a repeatable script.
- Choose and implement one shell source for the debrief kit: (a) publish the shell to the existing kit asset bucket/CDN and add the registry item the adapter reads, or (b) have the T-0185 adapter fetch the shell from the voice service. Record the choice in the ticket log.
- Ensure the shell's CSP/CDN declarations (`getCdnUrl`) work for the debrief kit.
- Add a router test that resolves the debrief shell without touching the Lambda path.

## Acceptance
- `kit_view("debrief")` lists views; `kit_view("debrief","<view>")` returns an embedded resource whose shell loads in Claude.
- Existing kits' shells are unaffected.

## Write scope
`kits/debrief` build config, `packages/mcp-server/src/router/app-resources.ts` or adapter short-circuit, registry/seed metadata, router tests.
