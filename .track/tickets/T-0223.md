## Goal

Freeze one inspectable plugin shape before adding more reusable connectors or
capabilities. Preserve the working debrief flow and avoid introducing an
orchestration framework.

## Scope

- SDK `PluginManifest` is canonical.
- Manifests declare `apiVersion`, provided capability contracts, required
  capability contracts, and required scopes.
- Legacy `capabilities`/`dependencies` fields remain compatibility metadata only.
- Debrief registrations declare real capability contracts and dependencies for
  persistence, memory, instructions, AI, HTTP, triggers, voice, proxy, kit,
  and scheduler.
- Registration validates the canonical manifest shape.
- Add focused contract tests.

## Explicit non-goals

- no workflow/graph/chain/model-routing abstraction;
- no universal connector catalog;
- no marketplace or dynamic installation;
- no removal of the debrief compatibility registry in this slice;
- no runtime dependency resolver yet (tracked as P1 follow-up).

## Acceptance

- SDK and debrief manifests are data-only and inspectable before invocation;
- a manifest without a capability declaration is rejected;
- debrief plugin telemetry and dogfood behavior remain green;
- SDK build and focused SDK/debrief tests pass;
- the plugin research record is linked from the beta execution plan.
