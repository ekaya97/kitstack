# defineTool()

Creates a typed tool definition. Tools are the actions an LLM can call in your kit.

## Signature

```ts
// With load and optional handler
function defineTool<T extends z.ZodType, TData>(config: {
  name: string;
  description: string;
  args: T;
  authorize?: (args: z.infer<T>, ctx: KitContext) => AuthzRequirement[];
  mode?: "assist" | "act";
  classification?: "public" | "internal" | "sensitive" | "destructive" | (string & {});
  load: (ctx: KitContext, args: z.infer<T>) => Promise<TData>;
  handler?: (ctx: KitContext, args: z.infer<T>) => Promise<KitToolResult>;
}): TypedToolWithLoad<T, TData>;

// With handler only (no load)
function defineTool<T extends z.ZodType>(config: {
  name: string;
  description: string;
  args: T;
  authorize?: (args: z.infer<T>, ctx: KitContext) => AuthzRequirement[];
  mode?: "assist" | "act";
  classification?: "public" | "internal" | "sensitive" | "destructive" | (string & {});
  handler: (ctx: KitContext, args: z.infer<T>) => Promise<KitToolResult>;
}): ToolDefinition;
```

## Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `name` | `string` | Yes | Tool name. Must be `snake_case`. |
| `description` | `string` | Yes | What the tool does. Must be >= 10 characters. Shown to the LLM. |
| `args` | `z.ZodType` | Yes | Zod schema defining the tool's arguments. |
| `mode` | `"assist" \| "act"` | No | `"assist"` (default) reads or prepares; `"act"` changes state or has external side effects. Sets the MCP `readOnlyHint`; maps to `kit:use` / `kit:act` grants on the hosted platform. |
| `classification` | `string` | No | Data sensitivity: `"public"`, `"internal"` (default when `mode` is set), `"sensitive"`, `"destructive"`, or your own label. `"destructive"` sets the MCP `destructiveHint`. |
| `authorize` | `(args, ctx) => AuthzRequirement[]` | No | Returns authorization requirements checked before the handler runs. See [Authorization](/docs/guides/authorization) for where they are enforced. |
| `load` | `(ctx, args) => Promise<TData>` | No | Data loading function. Reusable by view loaders. |
| `handler` | `(ctx, args) => Promise<KitToolResult>` | No | Handler that returns a formatted result. Required if `load` is omitted. |

At least one of `load` or `handler` must be provided.

## Handler parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `ctx` | `KitContext` | Request context. `ctx.db` is the Drizzle database; `ctx.identity` (`{ principal, actor }`) is the caller; also `params`, `connectors`, `log`, `telemetry`, `audit`, `session`, `channel`. |
| `args` | `z.infer<T>` | Validated arguments (Zod runs before the handler) |

## Returns

`ToolDefinition` — passed to [`defineKit()`](/docs/api/define-kit) in the `tools` array.

When `load` is provided, the returned object has a typed `.load()` method that view loaders can call directly.

## Behavior

- If only `load` is provided (no `handler`), the SDK auto-wraps it with [`kit.json()`](/docs/api/kit-helpers). The return value of `load` is serialized as pretty-printed JSON.
- If both `load` and `handler` are provided, the handler controls the response. The `load` function is available for view loaders to reuse.
- Arguments are validated with Zod before `authorize` and the handler run, both in the MCP server and in the test harness. Validation errors return `KitToolResult` with `isError: true`.

## Examples

### Handler-only tool

```ts filename="src/tools/add-contact.ts"
import { defineTool, kit } from "@kitstackco/sdk";
import { z } from "zod";
import { contacts } from "../schema";

export const addContact = defineTool({
  name: "add_contact",
  description: "Add a new contact to the CRM",
  mode: "act",
  args: z.object({
    name: z.string().describe("Contact's full name"),
    company: z.string().optional().describe("Company name"),
    email: z.string().optional().describe("Email address"),
  }),
  handler: async (ctx, args) => {
    const id = crypto.randomUUID();
    await ctx.db.insert(contacts).values({
      id,
      name: args.name,
      company: args.company ?? null,
      email: args.email ?? null,
    });
    return kit.text(`Contact "${args.name}" added (ID: ${id}).`);
  },
});
```

### Tool with load and handler

```ts filename="src/tools/list-contacts.ts"
import { defineTool, kit, type KitContext } from "@kitstackco/sdk";
import { z } from "zod";
import { contacts } from "../schema";

async function loadContacts(ctx: KitContext, args: { limit: number }) {
  return ctx.db.select().from(contacts).limit(args.limit);
}

export const listContacts = defineTool({
  name: "list_contacts",
  description: "List all contacts in the CRM",
  args: z.object({
    limit: z.number().optional().default(25).describe("Max results"),
  }),
  load: loadContacts,
  handler: async (ctx, args) => {
    const rows = await loadContacts(ctx, args);
    if (rows.length === 0) return kit.text("No contacts found.");
    return kit.text(rows.map((r) => `- ${r.name}`).join("\n"));
  },
});

// View loaders can reuse the query:
// listContacts.load(ctx, { limit: 100 })
```

### Load-only tool (auto-wrapped with kit.json)

```ts filename="src/tools/count-items.ts"
export const countItems = defineTool({
  name: "count_items",
  description: "Count all items in the database",
  args: z.object({}),
  load: async (ctx, args) => {
    const [row] = await ctx.db.select({ count: count() }).from(items);
    return { total: row.count };
  },
  // Returns: { "total": 42 } as formatted JSON
});
```

### Tool with authorization

```ts filename="src/tools/delete-deal.ts"
export const deleteDeal = defineTool({
  name: "delete_deal",
  description: "Delete a deal from the pipeline",
  args: z.object({
    dealId: z.string().describe("The deal ID to delete"),
  }),
  mode: "act",
  classification: "destructive",
  authorize: (args, ctx) => [
    { relation: "owner", objectType: "deal", objectId: args.dealId },
  ],
  handler: async (ctx, args) => {
    await ctx.db.delete(deals).where(eq(deals.id, args.dealId));
    return kit.text("Deal deleted.");
  },
});
```

## Notes

- Tool names must be `snake_case`. The regex is `/^[a-z][a-z0-9]*(?:_[a-z0-9]+)*$/`.
- Do not prefix tool names with the kit ID. Tools are always addressed through their kit (`kit(id, cmd)`).
- Use `.describe()` on every Zod field. These descriptions appear in the JSON Schema that the LLM uses to understand parameters.
- Descriptions under 10 characters are rejected. Over 200 characters triggers a warning.
- Related: [`defineKit()`](/docs/api/define-kit), [Kit helpers](/docs/api/kit-helpers)
