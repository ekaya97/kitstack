# defineView()

Creates a typed view definition. A View is declared once and can render in both
an MCP Apps chat iframe and the KitStack dashboard shell. The SDK supplies the
same typed host contract to both surfaces.

## Signature

```ts
function defineView<TLoader extends LoaderFn>(config: {
  id: string;
  name: string;
  description: string;
  loaders: readonly [TLoader];
  render: (
    data: Awaited<ReturnType<TLoader>>,
    host: ViewHost,
  ) => React.ReactNode;
  height?: number;
  permissions?: { clipboardWrite?: boolean };
  placeholder?: Awaited<ReturnType<TLoader>>;
}): ViewDefinition<TLoader>
```

## Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `id` | `string` | Yes | Stable URL-safe identifier. Must be `kebab-case`; it is also the router slug used in `kit_view(view: "id")`. |
| `name` | `string` | Yes | Human-readable name. Shown in DevKit sidebar. |
| `description` | `string` | Yes | Tells the LLM *when* to show this view (e.g., `"after adding contacts"`). |
| `loaders` | `readonly [LoaderFn]` | Yes | The View's typed server-side data loader set. The first loader is the primary loader executed by the current runtime. Created with [`defineLoader()`](/docs/api/define-loader). |
| `render` | `(data, host) => React.ReactNode` | Yes | Host-aware renderer. It receives the loader result and the frozen [`ViewHost`](#viewhost) contract. |
| `height` | `number` | No | Height in pixels for the iframe. |
| `permissions.clipboardWrite` | `boolean` | No | Allow writing to clipboard from the view. Default: `false`. |
| `placeholder` | `Awaited<ReturnType<TLoader>>` | No | Sample data for DevKit when the loader returns empty/null. |

## Returns

`ViewDefinition<TLoader>` — passed to [`defineKit()`](/docs/api/define-kit) in the `views` array.

## Examples

### Basic view

```ts filename="src/views/contacts/index.ts"
import { defineView } from "@kitstackco/sdk";
import { loader } from "./loader";
import { ContactsView } from "./View";

export default defineView({
  id: "contacts",
  name: "Contacts",
  description: "after adding or updating contacts",
  loaders: [loader],
  render: (data, host) => <ContactsView data={data} host={host} />,
  height: 500,
});
```

### View with placeholder

```ts filename="src/views/contact-detail/index.ts"
import { defineView } from "@kitstackco/sdk";
import { loader } from "./loader";
import { ContactDetailView } from "./View";

export default defineView({
  id: "contact-detail",
  name: "Contact Detail",
  description: "to view detailed contact info with deals and activity",
  loaders: [loader],
  render: (data, host) => <ContactDetailView data={data} host={host} />,
  placeholder: {
    contact: {
      id: "c1",
      name: "Jane Doe",
      company: "Acme Corp",
      email: "jane@acme.co",
    },
    deals: [
      { id: "d1", name: "Brand Refresh", value: 18000, stage: "proposal" },
    ],
    recentActivities: [
      { id: "a1", type: "meeting", description: "Kick-off call" },
    ],
  },
});
```

### View with permissions

```ts filename="src/views/export/index.ts"
export default defineView({
  id: "export",
  name: "Export Data",
  description: "to export data as CSV or JSON",
  loaders: [loader],
  render: (data, host) => <ExportView data={data} host={host} />,
  permissions: {
    clipboardWrite: true,
  },
});
```

## File structure convention

The build pipeline expects this file layout for each view:

```
src/views/{slug}/
  index.ts      # defineView() call
  loader.ts     # Server-side data function
  View.tsx       # React component
```

The component file must be at `src/views/[slug]/View.tsx`. The build fails if it's missing.

## ViewHost

`render(data, host)` receives a `ViewHost` in every runtime:

```ts
interface ViewHost {
  kind: "chat" | "shell";
  size: { width: number; height: number };
  navigate: (viewId: string, params?: Readonly<Record<string, unknown>>) => void | Promise<void>;
  identity: { principal: string; actor: string; delegation?: string | Readonly<Record<string, unknown>> };
  theme: { mode: "light" | "dark" };
}
```

Use `host.kind` only for small surface-specific presentation differences. Keep
business logic and data loading independent of the host. `navigate()` asks the
host to open another View in the same kit; the host remains responsible for
routing and authorization. `identity` is host-provided context for display or
delegated actions, not a replacement for server-side authorization.

The chat host is the MCP Apps iframe used by Claude and other MCP clients. The
shell host is the KitStack dashboard surface. Both hosts use the same View
renderer, so a kit does not need a chat View and a dashboard View for the same
workflow.

## Notes

- View slugs must be `kebab-case`. The regex is `/^[a-z][a-z0-9]*(?:-[a-z0-9]+)*$/`.
- `id` is the public identifier; the SDK normalizes it to the internal `slug`
  field used by the current build and router implementations.
- Placeholders are typed against the loader's return type. TypeScript errors if the shape doesn't match.
- Placeholders are stripped from the production build and stored in `kit._placeholders`. They only appear in the DevKit.
- Changes to placeholder data or view config require restarting `kitstack dev`. Only `View.tsx` changes are hot-reloaded.
- Related: [`defineLoader()`](/docs/api/define-loader), [`defineKit()`](/docs/api/define-kit), [Views concept](/docs/concepts/views)
