# Kit Result Helpers

The `kit` object provides factory functions for creating `KitToolResult` objects — the return type of every tool handler.

```ts
import { kit } from "@kitstackco/sdk";
```

## kit.text()

Returns a text result. Best suited for read operations and informational responses.

```ts
function text(text: string): KitToolResult
```

```ts filename="src/tools/example.ts"
return kit.text(`Found ${rows.length} contacts matching "${args.query}".`);
```

**Result:**
```json
{ "content": [{ "type": "text", "text": "Found 3 contacts matching \"Alice\"." }] }
```

<Note>
`kit.text()` is intended for **read operations only**. For write operations (create, update, delete), use the [mutation result helpers](#kitcreated--kitupdated--kitdeleted) below so that entity IDs are returned in a structured format for workflow chaining.
</Note>

## kit.json()

Returns pretty-printed JSON. Used for structured data responses.

```ts
function json(data: unknown): KitToolResult
```

```ts filename="src/tools/example.ts"
return kit.json({ contacts: rows, total: rows.length });
```

**Result:**
```json
{ "content": [{ "type": "text", "text": "{\n  \"contacts\": [...],\n  \"total\": 5\n}" }] }
```

<Note>
`kit.json()` is what the SDK uses to auto-wrap load-only tools. If your tool defines `load` without a `handler`, the return value of `load` is passed through `kit.json()` automatically.
</Note>

## kit.error()

Returns an error result. The LLM sees this as a failed tool call and can respond accordingly.

```ts
function error(text: string): KitToolResult
```

```ts filename="src/tools/example.ts"
return kit.error("Cannot delete a deal in 'closed-won' stage.");
```

**Result:**
```json
{ "content": [{ "type": "text", "text": "Cannot delete a deal in 'closed-won' stage." }], "isError": true }
```

## kit.notFound()

Returns a standardized "not found" error.

```ts
function notFound(entity: string, id: string): KitToolResult
```

```ts filename="src/tools/example.ts"
return kit.notFound("contact", args.contactId);
```

**Result:**
```json
{ "content": [{ "type": "text", "text": "contact with id \"abc123\" not found" }], "isError": true }
```

## kit.validationError()

Returns a validation error for cases Zod doesn't catch (e.g., business logic constraints).

```ts
function validationError(message: string): KitToolResult
```

```ts filename="src/tools/example.ts"
return kit.validationError("Start date must be before end date.");
```

## kit.conflict()

Returns a conflict error when the current resource state prevents the operation.

```ts
function conflict(message: string): KitToolResult
```

```ts filename="src/tools/example.ts"
return kit.conflict("A sequence with that name already exists.");
```

## kit.created() / kit.updated() / kit.deleted()

Composable mutation result helpers for write tools. Each returns a `KitResultFragment` describing what changed.

```ts
function created(id: string, entityType: string, message: string): KitResultFragment
function updated(id: string, entityType: string, message: string): KitResultFragment
function deleted(id: string, entityType: string, message: string): KitResultFragment
```

```ts filename="src/tools/example.ts"
const fragment = kit.created(id, "contact", `Contact "${args.name}" created.`);
```

## kit.result()

Composes one or more `KitResultFragment` values into a `KitToolResult`. Accepts a single fragment or an array.

```ts
function result(fragment: KitResultFragment): KitToolResult
function result(fragments: KitResultFragment[]): KitToolResult
```

```ts filename="src/tools/add-contact.ts"
const id = nanoid();
await db.insert(contacts).values({ id, name: args.name });
return kit.result(kit.created(id, "contact", `Contact "${args.name}" added.`));
```

For batch operations, pass an array:

```ts filename="src/tools/import-contacts.ts"
const fragments = inserted.map((c) =>
  kit.created(c.id, "contact", `Imported "${c.name}".`)
);
return kit.result(fragments);
```

<Warning>
Write tools **must** use `kit.result(kit.created(...))` (or `updated`/`deleted`) instead of `kit.text()`. This returns entity IDs in a structured format that enables workflow chaining — the LLM can pass the returned ID to subsequent tool calls.
</Warning>

### KitResultFragment type

`KitResultFragment` is exported from `@kitstackco/sdk` for custom operations beyond create/update/delete:

```ts
import { KitResultFragment } from "@kitstackco/sdk";
```

## KitToolResult type

All helpers return this type:

```ts
interface KitToolResult {
  content: KitToolContentBlock[];
  isError?: boolean;
}

type KitToolContentBlock =
  | { type: "text"; text: string }
  | { type: "resource"; resource: { uri: string; mimeType: string; text: string } };
```

## Notes

- These helpers return objects — they don't throw. Use them for errors that the LLM should see and can act on (e.g., "not found", "permission denied").
- For programming mistakes that should never reach production, throw a `KitStackError` subclass instead.
- The `isError` flag tells the LLM the tool call failed. It typically acknowledges the error and suggests alternatives.
- Related: [`defineTool()`](/docs/api/define-tool), [Errors](/docs/api/errors)
