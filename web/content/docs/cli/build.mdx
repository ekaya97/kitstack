# kitstack build

Validate your kit and bundle it for deployment. Produces a server bundle, view modules, CSS, shell HTML, a manifest, and a container context. Runs locally; no KitStack account is needed.

## Usage

```bash filename="Terminal"
npx kitstack build
```

Or with a custom kit root:

```bash filename="Terminal"
npx kitstack build --config ./kits/crm
```

## Flags

| Flag | Description |
|------|-------------|
| `--config <path>` | Kit root directory. Default: current directory. |
| `--container` | Also build the generated container context into an image with Docker or Podman. |
| `--engine <name>` | Container engine for `--container`. Default: `KITSTACK_CONTAINER_ENGINE` or `docker`. |
| `--image <ref>` | Image reference. Default: `<kit-id>:<version>`. |
| `--base-image <ref>` | Base image for the generated Containerfile. Default: `node:22-bookworm-slim`. |
| `--sign-key <path>` | Sign the artifact metadata with the contents of this file. |
| `--help`, `-h` | Show help. |

## Output

Build artifacts are written to `.kitstack/build/`:

| File | Description |
|------|-------------|
| `kit.mjs` | Server bundle (esbuild, ESM) |
| `kit.zip` | Lambda archive |
| `manifest.json` | Build metadata with hashes, sizes, SDK version |
| `shell.html` | MCP Apps HTML shell |
| `views/vendor.js` | React + ReactDOM (shared across views) |
| `views/shared.js` | SDK hooks and shared components |
| `views/[kitId]/[slug].js` | Per-view entry modules |
| `views/style.css` | Compiled Tailwind CSS |
| `container/` | Generated container context (`Containerfile`, runner, bundle) |
| `kitstack.yaml` | Compose-compatible deployment file |
| `artifact.json` | Artifact metadata with digest (signed with `--sign-key`) |

<Note>
The generated container runs the kit's invocation handler (`POST /` or `/invoke`, plus `GET /healthz`) for KitStack's hosting adapters. It is not an MCP endpoint. To run your kit as an MCP server in a container, see [Self-hosting: containers](/docs/guides/self-hosting#containers).
</Note>

## Build pipeline

0. **Generate migrations** — runs `drizzle-kit generate` if `drizzle.config.ts` exists (continues with existing migrations if it fails)
1. **Load** — imports `kit.config.ts`, runs `defineKit()` validations
2. **Validate migrations** — executes all SQL against an in-memory SQLite database
3. **Bundle server** — esbuild with `@libsql/client`, `drizzle-orm`, `zod` externalized
4. **Generate view entries** — creates mount-point code for each view
5. **Bundle views** — Vite with `manualChunks` (React → vendor, hooks → shared)
6. **Compile CSS** — Tailwind processes `src/views/styles.css`
7. **Generate shell** — bakes kit config into the MCP Apps shell HTML
8. **Write manifest** — `manifest.json` with SHA-256 hashes (12 hex chars)
9. **Emit container artifact** — `container/`, `kitstack.yaml`, `artifact.json`

## Validations

| Check | Error | Description |
|-------|-------|-------------|
| Kit config loads | `TOOL_*`, `KIT_*` | Invalid names, short descriptions, duplicates |
| View.tsx files exist | — | Every declared view must have a component file |
| Migration SQL valid | — | Each statement executed against in-memory SQLite |
| No DROP statements | `MIGRATION_DROP_FORBIDDEN` | Hard rule, not configurable |

## Size warnings

| Threshold | Message |
|-----------|---------|
| Server bundle > 1 MB | "Consider splitting large dependencies" |
| View module > 500 KB | "Consider code-splitting or reducing dependencies" |
| Shared chunk > 500 KB | "May slow down initial view loads" |

These are warnings, not hard failures. To fix:

- **Server bundle:** ensure `@libsql/client`, `drizzle-orm`, `zod` are externalized
- **View modules:** import specific subpaths (e.g., `date-fns/format` not `date-fns`)

## Notes

- Build validation is intentionally stricter than `kitstack dev`. Dev should be fast; build should catch everything before deployment.
- Migration validation runs against a fresh in-memory database, catching SQL that would fail on a new user's database.
- The manifest's `sdkVersion` is read from the installed `@kitstackco/sdk` package.
