# kitstack deploy

Build your kit and deploy it, privately, to the hosted KitStack platform. Uploads the bundle, views, and shell, and registers the kit so you can activate it from the KitStack dashboard.

<Note>
`kitstack deploy` needs a KitStack account and the hosted KitStack API (`https://kitstack.co`). It does not apply to self-hosting: to run a kit on your own infrastructure, use [`kitstack serve`](/docs/cli/serve) or [`serve()`](/docs/guides/self-hosting).
</Note>

## Usage

```bash filename="Terminal"
npx kitstack login     # once per machine
npx kitstack deploy
```

## Flags and subcommands

| Flag | Description |
|------|-------------|
| `--config <path>` | Kit root directory. Default: current directory. |
| `approve <request-id>` | Approve a pending deployment request (organization admins only). |
| `--help`, `-h` | Show help. |

## What it does

1. Checks for credentials from `kitstack login` (exits with "Not logged in" otherwise)
2. Runs `drizzle-kit generate` and the full [`kitstack build`](/docs/cli/build) — you do not need to build first
3. Uploads `manifest.json`, the server bundle (`kit.zip`), the shell, views, and previews to the KitStack API
4. Prints the result

```
  ✓ Kit "my-kit" deployed (private)
    Tools: 2
    Views: 1

  Activate it from your dashboard at https://kitstack.co/dashboard?tab=developer
```

If your organization requires approval, the deployment becomes a request instead:

```
  ⏳ Deployment request <request-id> is awaiting admin approval.
    An admin can run: kitstack deploy approve <request-id>
```

## kitstack publish

`kitstack publish` (listing a kit publicly in the marketplace) is not available yet. Running it prints a notice and exits with code `1`. Deployed kits are private.

## Deployment architecture

Deployed kits run as sandboxed Lambda functions:

- **Runtime:** Node.js 22 on arm64
- **Code:** loaded from S3 (`bundles/[kitId]/kit.mjs`)
- **Dependencies:** shared Lambda layer (`drizzle-orm`, `@libsql/client`, `zod`, `nanoid`)
- **IAM:** minimal role — only `lambda:InvokeFunction` on the MCP router
- **Database:** no credentials in env vars. Queries go through a proxy authenticated by per-invocation tokens (60s TTL)

## Environment override

`KITSTACK_API_URL` overrides the API base URL (default `https://kitstack.co`).

<Note>
First-party and third-party kits use the same pipeline. There is no separate deploy path for platform-maintained kits.
</Note>
