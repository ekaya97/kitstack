# kitstack dev

Start a local MCP server for development. By default, connects to the KitStack relay and gives you a public URL that any MCP client can use — with live view updates.

## Usage

```bash filename="Terminal"
npx kitstack dev [flags]
```

## Flags

| Flag | Description |
|------|-------------|
| `--stdio` | Use stdio transport instead of relay (for offline development). |
| `--views` | Start the DevKit HTTP server for view development without an LLM client. |
| `--config <path>` | Path to `kit.config.ts`. Default: `./kit.config.ts`. |
| `--db <path>` | Path to the SQLite database file. Default: `.kitstack/dev.db`. |
| `--reset-db` | Delete the dev database and re-run migrations on startup. |
| `--port <number>` | Port for the DevKit server. Default: `5174`. Only used with `--views`. |

## Default: relay mode

```bash filename="Terminal"
npx kitstack dev
```

This is the primary development workflow. The dev server:

1. Loads your kit config and provisions a local SQLite database
2. Connects to the KitStack relay via WebSocket
3. Prints a public URL that any MCP client can connect to

```
  Relay connected. Session URL:
  https://mcp.kitstack.co/dev/a3f2b1c8

  Add this URL to your LLM client's MCP server list.
```

### Live view development

In relay mode, view assets are served through the relay from your local Vite dev server. The workflow:

1. Have the LLM call `kit_view` once to render a view
2. Edit `View.tsx`, save
3. Refresh the page — your update appears on the previous tool call

No need to ask the LLM to re-invoke the tool. The view modules get hot-replaced on every page refresh, fetching the latest code from your local Vite. Large shared dependencies (React, ReactDOM) are loaded from CDN to avoid WebSocket message limits — only your kit-specific code goes through the relay.

### Reconnection

If the WebSocket connection drops, the relay client reconnects automatically with exponential backoff (1s, 2s, 4s, ... capped at 30s). The backoff resets on successful connection.

## stdio mode

```bash filename="Terminal"
npx kitstack dev --stdio
```

For offline development or when your LLM client supports launching local processes. Reads JSON-RPC from stdin, writes responses to stdout.

Configure your client to launch the process directly:

```json filename="claude_desktop_config.json"
{
  "mcpServers": {
    "my-kit": {
      "command": "npx",
      "args": ["kitstack", "dev", "--stdio"],
      "cwd": "/path/to/my-kit"
    }
  }
}
```

<Warning>
In stdio mode, never `console.log()` in tool handlers. Anything written to stdout corrupts the JSON-RPC stream. Use `console.error()` for debug output. This does not apply in relay mode.
</Warning>

## DevKit mode

```bash filename="Terminal"
npx kitstack dev --views
```

Opens a local HTTP server at `http://localhost:5174` for developing views without an LLM client:

- Sidebar listing all views
- Double-iframe viewport (same architecture as production)
- Data inspector (editable JSON, shows LOADER/PLACEHOLDER/EDITED source)
- Tool call logger
- Viewport sizing controls

## Startup sequence

1. Parse flags
2. Load `kit.config.ts` via dynamic import (runs `defineKit()` validation)
3. Run `drizzle-kit generate` if `drizzle.config.ts` exists
4. Provision SQLite database at `.kitstack/dev.db` (runs migrations)
5. Create MCP handler
6. Connect to relay (default) or start stdio transport

## Database management

The dev database is a SQLite file at `.kitstack/dev.db`. Migrations run on every startup using `CREATE TABLE IF NOT EXISTS`.

<Warning>
`CREATE TABLE IF NOT EXISTS` is idempotent for table names but ignores column changes. When you modify columns in `src/schema.ts`, use `--reset-db` to recreate the database from scratch.
</Warning>

```bash filename="Terminal"
npx kitstack dev --reset-db
```

## Relay vs stdio

| | Relay (default) | stdio (`--stdio`) |
|---|---|---|
| **Setup** | `kitstack login` once, then `kitstack dev` | Configure client to launch the process |
| **Client support** | Any MCP client with HTTP support | Clients that support subprocess launch |
| **Live views** | Yes — assets served through relay from Vite | No live view serving |
| **Network** | Requires outbound WSS | No network needed |
| **Restartability** | Client keeps the same URL | Must restart the client connection |
