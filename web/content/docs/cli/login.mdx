# kitstack login

Authenticate the CLI with your KitStack account. Requires the hosted KitStack service (`https://kitstack.co`) and an account there.

Needed only for commands that talk to the hosted platform: relay mode (`kitstack dev` without flags), `kitstack deploy`, `kitstack grants`, and `kitstack connectors bind`. Not needed for `init`, `dev --local`, `dev --stdio`, `call`, `build`, or `serve`.

## Usage

```bash filename="Terminal"
npx kitstack login
```

## Flags

| Flag | Description |
|------|-------------|
| `--force` | Re-authenticate even if credentials already exist. |

## How it works

1. A temporary HTTP server starts on `127.0.0.1:9876` (falls back to a random port if occupied).
2. Your browser opens to `https://kitstack.co/cli/authorize`.
3. You authenticate with your KitStack account (redirects to login if needed).
4. Click "Authorize" — a session token is created.
5. The browser redirects to the localhost callback with the token.
6. Credentials are saved to `~/.kitstack/credentials.json`.

```
$ npx kitstack login

  Opening browser to authenticate with KitStack...
  If the browser doesn't open, visit:
  https://kitstack.co/cli/authorize?callback=…

  Authenticated as dev@example.com.
  Token saved to ~/.kitstack/credentials.json
```

The flow times out after 2 minutes if no callback is received.

## Credentials

Stored at `~/.kitstack/credentials.json` with `0600` permissions:

```json
{
  "token": "abc123...",
  "email": "dev@example.com",
  "authenticatedAt": "2026-04-25T10:30:00.000Z"
}
```

CLI tokens are standard BetterAuth session tokens (same format as the web app) with a 1-year expiry. They can be revoked from the web app's session management UI.

## Commands that use your login

| Command | What it does on the hosted platform |
|---------|-------------------------------------|
| `kitstack dev` (no flags) | Connects to the dev relay. Falls back to local mode when not logged in. |
| `kitstack deploy` | Deploys the kit privately. See [`kitstack deploy`](/docs/cli/deploy). |
| `kitstack grants list \| grant \| revoke` | Lists or changes authorization grants (`kit:use`, `kit:act`, …) on the hosted platform. Mutations need `--yes`. |
| `kitstack connectors bind <connector-id>` | Binds an organization connector using secret references (`--config`, `--secret-ref name=ref`, `--yes`). |

None of these affect a self-hosted server. Self-hosted connectors and authorization are configured in code; see [Self-hosting](/docs/guides/self-hosting).

## Environment override

Override the auth URL for staging or local development:

```bash filename="Terminal"
KITSTACK_AUTH_URL=http://localhost:3000/cli/authorize npx kitstack login
```

## Notes

- Login is idempotent. Running it again when credentials exist prints a message and exits (unless `--force` is passed).
- The callback server binds to `127.0.0.1` (not `0.0.0.0`) to avoid macOS firewall prompts.
- Credentials persist across sessions. You only need to log in once per machine.
