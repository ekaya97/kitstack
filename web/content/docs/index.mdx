# KitStack SDK

MCP is a powerful standard, but building with it today is rough. You need to learn the protocol, implement JSON-RPC, handle auth and OAuth, manage databases, set up deployment infrastructure, and troubleshoot client-specific quirks — before you even write your first tool.

KitStack abstracts all of that away. You write business logic and UI. The SDK handles the MCP protocol, the platform handles infrastructure.

## What is a kit?

A kit is a lightweight MCP app that gives an LLM domain-specific capabilities. Think of kits as apps on an app store — focused utility tools like a CRM, an expense tracker, or a sequence builder. They bridge the gap between LLM conversations and long-term persistence without the complexity of building and hosting a full MCP server.

```ts filename="kit.config.ts"
import { defineKit, defineTool, kit } from "@kitstackco/sdk";
import { z } from "zod";

const addItem = defineTool({
  name: "add_item",
  description: "Add a new item to the list",
  args: z.object({
    name: z.string().describe("Name of the item"),
  }),
  handler: async (db, args, ctx) => {
    return kit.text(`Item "${args.name}" added.`);
  },
});

export default defineKit({
  id: "my-kit",
  version: "1.0.0",
  name: "My Kit",
  description: "A simple item tracker",
  schema: {},
  migrationsDir: resolve(import.meta.dirname, "migrations"),
  instructions: "Use this kit to manage items for the user.",
  tools: [addItem],
});
```

Define your tools, define your kit, deploy. Start using it in any MCP-compatible LLM client.

## What makes KitStack different

### DevKit — WYSIWYG development for MCP apps

Run `kitstack dev` and get a public URL. No port forwarding, no tunnels, no local stdio setup. The relay serves your kit to any MCP client over the internet, and your view changes are served in real-time from your local Vite dev server — what you see is what's deployed.

```bash filename="Terminal"
npx kitstack dev
#   Relay connected. Session URL:
#   https://mcp.kitstack.co/dev/a3f2b1c8
```

Edit `View.tsx`, refresh the page, and your update appears immediately on the previous tool call. No need to ask the LLM again — the modules get hot-replaced on refresh. The dev experience is identical to the deployed experience.

For rapid UI iteration without an LLM client, use the DevKit directly:

```bash filename="Terminal"
npx kitstack dev --views
```

This opens a local server with a sidebar listing all views, an editable data inspector, a tool call logger, and viewport sizing controls. Build and preview your views the same way you'd build a React app — then see the exact same result inside your LLM client.

### Two-tool progressive discovery

Instead of registering every action as a separate MCP tool, all your kits are composed behind exactly **two tools**: `kit` and `kit_view`. This solves the scaling problem where dozens of tool definitions compete for the LLM's attention. See [How kits work](/docs/concepts/kits) for the full design.

### Isolated databases, zero complexity

Each user gets their own SQLite database for each kit. Completely separate — not row-level isolation, not shared tables, **different databases**. This eliminates the entire class of problems around LLM data access and permissions. See [Database](/docs/concepts/database) for details.

### One connection, dynamic kits

KitStack is a single MCP connection. Users activate and deactivate kits from the dashboard without reconnecting their LLM client. One auth, one connection, and the user manages what's available from a single dashboard — like an app store that doesn't require restarting the app after each install.

## Current limitations

**No network.** Kits can't call external APIs — every piece of data enters through the user's conversation. This is a temporary limitation. If your kit needs external endpoints, reach out at hello@kitstack.co.

**No background execution.** Kits only run when the LLM calls them. No scheduled tasks, no reminders, no triggers.

**Single-user, single-session.** No collaboration, no shared state between users. Multi-user collaborative kits are on the roadmap.

**Client behavior varies.** Some LLM clients defer tool loading behind a search index. KitStack's tool description is designed for this, but discoverability depends on how each client handles deferred tools.
